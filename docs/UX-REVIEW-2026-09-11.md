# Village journey review — 11 September 2026

The main problem was the gap between choosing support and doing something useful with it. The site saved choices correctly, but repeated selection screens, hidden service actions and unavailable forms made the journey feel unfinished.

## Code review

- Security: progress is bounded by saved service slugs and three allowlisted values. Restored drafts discard arbitrary fields. No contact data or progress is sent as analytics. Existing server validation and acknowledgement requirements remain intact.
- Correctness: existing saved categories migrate without loss; removal clears only that category’s progress; clear/undo restores a complete draft. Progress is explicitly a personal record, not confirmation from a provider.
- Performance: no dependencies added. Content routes remain prerendered. The homepage no longer hydrates an unnecessary separate service-selector state.
- Maintainability: choosing, saved support and exports are separate components. The shared catalogue and source records drive the experience. Existing service URLs and the circle logo are preserved.

## Validation and remaining limits

The production build and TypeScript check pass; 28 automated tests pass, including new progress persistence, migration and data-minimisation coverage. The route audit covers 19 pages, 43 internal links/assets, two missing-page cases and three metadata resources without failures.

Browser checks cover the homepage → service → village journey, five choices through the shortened builder, progress after refresh, map navigation/addition, clear/undo, last-item removal/undo, provider-name search, empty-search recovery, legacy links, mobile navigation and keyboard dismissal of the desktop category menu. All 19 pages were inspected at 320px: one main heading each, no horizontal overflow and no broken section anchors. All eight service pages place the provider before the explanatory sections on mobile; desktop/tablet layouts were also checked. A service link was followed successfully into a new tab. The visible text export was checked for all five categories, provider URLs and saved progress. Copy/download/print use browser capabilities; the text version offers a fallback. Native clipboard, download-file and print-output handling is not independently verified in the embedded browser.

The eight external source pages were rechecked on their official websites: [Dinner Ladies](https://www.dinnerladies.com.au/pages/delivery-info), [Nanager](https://nanager.com.au/), [Australian Breastfeeding Association](https://www.breastfeeding.asn.au/get-help), [PANDA](https://www.panda.org.au/), [Playgroup Victoria](https://www.playgroup.org.au/find/), [Tweddle](https://www.tweddle.org.au/), [Maid to Clean](https://www.maidtoclean.com.au/) and [The Carellective](https://www.carellective.com.au/home-care-organisation). This verifies the public starting points, not provider suitability, current availability or Village partnerships.

Village’s receiving inbox is still unconfigured in this preview. Real delivery, downstream email and bookings are not claimed as tested or enabled. The current product is a useful service-discovery and personal-planning experience; a fuller provider directory and direct enquiries remain the next product milestone.
